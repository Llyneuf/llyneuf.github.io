## Обзор

Этот сайт — моя публичная база: место для проектов, заметок девлога, ссылок на стримы, контактов и небольших экспериментов, которые слишком связаны между собой, чтобы держать их разбросанными по разным платформам.

Цель не в том, чтобы сделать огромный портфолио-сайт. Цель — сделать **чистый личный хаб**, который может расти постепенно: одна новая страница проекта, одна запись в девлог, один лучший скриншот, одна более понятная ссылка за раз.

Сейчас сайт уже работает как статический проект на GitHub Pages, но структура выстраивается так, чтобы его было приятно редактировать и в будущем. Короткие карточки проектов живут в `src/data/projects.js`, а длинные тексты о проектах — в виде markdown-файлов в `src/content/projects`.

## Что делает сайт

- Показывает главную идентичность и визуальное направление на главной странице.
- Собирает активные, приостановленные и завершённые проекты в одном хабе.
- Даёт каждому проекту собственную страницу, которой можно поделиться.
- Хранит записи девлога отдельно от описаний проектов.
- Даёт ссылки на важные платформы, не превращая страницу в свалку социальных ссылок.
- Имеет кастомную страницу `404.html` для несуществующих или будущих URL.

## Текущая структура

Проект разделён на два вида контента.

**Структурированные данные** живут в `src/data`. Это лучший вариант для повторяющихся полей: названия проектов, слаги, статусы, теги, превью-изображения и внешние ссылки.

**Длинные тексты** живут в markdown. Это лучший вариант для естественного письма: абзацы, заметки, контекст, шаги установки или мысли о проекте, которые не стоит втискивать в маленькую карточку.

Например, карточка на главной может оставаться короткой:

- название
- статус
- краткое описание
- короткая заметка о прогрессе
- несколько компактных деталей карточки

Полная страница проекта может быть более развёрнутой:

- обзор
- текущий фокус
- технические заметки
- планы на будущее
- полезные ссылки
- заметки по редактированию

## Почему Markdown

Markdown делает сайт проще в обслуживании, потому что страницы проектов можно писать как обычные заметки, а не код.

Это значит, что я могу редактировать тексты в **Obsidian**, сохранять читаемость текста и при этом позволять сайту рендерить их как часть страницы проекта.

Текущий рендерер поддерживает основное, что нужно для этого сайта:

- заголовки `##`, `###` и `####`
- обычные абзацы
- маркированные списки
- **жирный текст**
- `инлайн-код`
- ссылки вида [репозиторий на GitHub](https://github.com/Llyneuf/llyneuf.github.io)
- горизонтальные разделители через `---`

## Визуальное направление

Сайт должен ощущаться личным, тёмным, мягким и немного театральным, но при этом оставаться читаемым. Он не должен выглядеть как корпоративный дашборд или типовой лендинг.

Главные визуальные якоря:

- имя Llyneuf
- арт с персонажем
- тёмные фоны с мягким контрастом
- циановые метки для структуры
- розовые акценты для призывов к действию
- компактные карточки для проектов и записей девлога

Дизайн ещё развивается, но направление уже чётче, чем в первой версии: меньше заглушек, больше реального контента и больше страниц, которыми можно делиться напрямую.

## Технические заметки

Сайт сейчас использует:

- **React** для компонентов.
- **Vite** для локальной разработки и продакшн-сборок.
- **GitHub Pages** для хостинга.
- Кастомный домен: [llyneuf.xyz](https://llyneuf.xyz/).
- Статические файлы данных для повторяющегося контента сайта.
- Markdown-файлы для длинных текстов о проектах.

Бэкенда пока нет. Это сделано намеренно: сайт должен оставаться простым, пока контент и структура ещё меняются.

## Что дальше

Следующие полезные улучшения касаются в основном качества контента.

- Заменить слабые или несоответствующие превью-изображения проектов.
- Привести все изображения проектов к единому формату `16:9`.
- Написать полноценные страницы для Ninette, Warudo Horror Room и Peripeteia.
- Добавить больше записей в девлог с реальными скриншотами прогресса.
- Доработать мобильную вёрстку страниц проектов и хаба.

После этого можно двигаться к более удобному процессу редактирования. Наиболее перспективный путь — продолжать использовать Obsidian для написания и давать сайту подтягивать markdown-файлы во время сборки.

## Заметки по редактированию

Этот файл задуман как пример того, как можно писать будущие страницы проектов.

Используй абзацы, когда проект требует объяснения. Используй списки, когда читателю нужно быстро просмотреть информацию. Используй `инлайн-код` для путей, имён файлов и технических названий. Используй **жирный** только для реального акцента, а не для каждого важного слова.

Если страница начинает казаться слишком длинной, раздели её на секции с заголовками `##`. Если секция кажется слишком плотной, используй короткий маркированный список.
